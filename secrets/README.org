#+title: Secrets

Secrets are managed with age encryption and integrated with nix using the wonderful [[https://github.com/ryantm/agenix?tab=readme-ov-file#ageidentitypaths][Agenix]] by ryantm.

* Layout

Secrets are grouped by what they are, not by which service reads them:

| Directory      | Contents                                                              |
|----------------+-----------------------------------------------------------------------|
| =oidc/=        | OIDC client secrets, each paired with its =*-hash.txt= digest         |
| =credentials/= | Anything that must be sourced or set by hand                          |
| =passwords/=   | Secrets we issue ourselves: admin passwords, tokens we mint           |
| =keys/=        | Key material a service signs or encrypts with, plus the Clevis blobs  |

The line between =credentials/= and =passwords/= is how the value comes to
exist. A credential has to be fetched or set manually -- from a third party
(Fastmail, Cloudflare) or from a running service that alone can mint it
(=tailscale-preauth= from headscale, =ntfy-webpush-keys-env= from ntfy). Everything
in =passwords/= we can generate ourselves, at any time, from nothing.

=keys/= is separate again: material a service signs and encrypts its own data
with, rather than presents to something else. It is generated by
[[file:init-keys.sh][init-keys.sh]], and must be held identical across every node running that
service.

* Editing Secrets

The list of secrets that can be created/edited is in [[file:secrets.nix]] and are populated with the following command.

#+begin_src shell
EDITOR=vim nix run github:ryantm/agenix -- -e credentials/cloudflare-api-env.age
#+end_src

If you change ssh keys and need to re-encrypt your age secrets the following command will re-encrypt all of them.

#+begin_src shell
EDITOR=vim nix run github:ryantm/agenix -- -r
#+end_src

* Key material

[[file:init-keys.sh][init-keys.sh]] generates everything in =keys/= that does not already exist, and
registers it in [[file:secrets.nix]]. It never overwrites: these keys sign and
encrypt data that already exists, so replacing one is destructive. A fresh
=authelia-storage= leaves the encrypted Postgres columns unreadable, and a
fresh =lldap-key-seed= invalidates every key derived from it.

#+begin_src shell
./init-keys.sh --list  # show what exists
./init-keys.sh         # generate whatever is missing
#+end_src

To rotate a key deliberately, delete the file and re-run.

* Authelia secrets

The individual commands behind =init-keys.sh=, for reference.

The majority of Authelia secrets are just 64 character long random strings that can be easily generated.

#+begin_src shell
nix run 'nixpkgs#authelia' -- crypto rand --length 64 --charset alphanumeric
#+end_src

a notable exception is =authelia-oicd-issuer.pem= which is actually an RSA keypair.

#+begin_src shell
nix run 'nixpkgs#authelia' -- crypto pair rsa generate
#+end_src

Apparently Authelia does support DSA keys which could be interesting in future.

** OIDC secrets

Most often we want to create OIDC keys, consisting of an encrypted secret
(supplied to the application) and a hash (given to Authelia). We can get both at
once with:

#+begin_src shell
nix run 'nixpkgs#authelia' -- crypto hash generate argon2 --random --random.length 72 --random.charset rfc3986
#+end_src

The secret itself should be put in =oidc/<service>-secret.age=, and the hash in =oidc/<service>-hash.txt=.

In order to work with [[file:~/Documents/Projects/golgi/modules/auth/clients.nix][clients.nix]] nicely, it is important that =<service>= be the
lowercase name of the "app" from [[file:~/Documents/Projects/golgi/site.nix][site.nix]], with dashes instead of spaces (e.g.
=home-assistant= instead of =Home Assistant=).

* Cloudflare

Any secret that ends in =env= such as =credentials/cloudflare-api-env.age= is actually an environment file not a raw secret.

#+begin_example
CLOUDFLARE_AUTH_TOKEN=<super secret token>
#+end_example
